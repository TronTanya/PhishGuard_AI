# PhishGuard AI

**Анализ признаков фишинга в ссылках и сообщениях**

PhishGuard AI — учебное приложение для студенческой научной конференции. Оно проверяет адрес ссылки или текст сообщения, находит признаки, типичные для фишинга, и объясняет каждый из них на русском языке.

> Инструмент использует **прозрачные правила, а не обученную модель машинного обучения**. Слово «AI» в названии отражает тематику проекта. Приложение находит *подозрительные признаки*, а не подтверждает вредоносность. Низкий индекс не гарантирует безопасность ссылки.

## Возможности

- **Проверка ссылки**: разбор адреса (схема, фактический хост, регистрируемый домен, поддомен, путь), 12 правил с объяснениями.
- **Проверка сообщения**: текстовое поле или файл `.txt` (UTF-8, до 1 МБ), 6 групп фраз на русском и английском, отдельный анализ каждой найденной ссылки (не более 10 уникальных).
- **Индекс подозрительных признаков** 0–100 с показом вклада каждого правила.
- **Рекомендации**, связанные с найденными признаками.
- **HTML-отчёт** для скачивания: пароли и секретные параметры скрыты, ссылки некликабельны.
- **Демонстрационные примеры** загружаются одной кнопкой и анализируются настоящим движком правил.
- **Эксперимент** на размеченном учебном наборе: матрица ошибок, precision, recall, F1.

Приложение работает **локально и офлайн**: ссылки не открываются, домены не разрешаются через DNS, страницы не загружаются, внешние сервисы не используются. Введённые данные хранятся только в памяти текущей сессии и автоматически никуда не записываются.

## Установка и запуск

Требуется Python 3.11 или новее.

### Windows (PowerShell)

```powershell
cd PhishGuardAI
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

Если PowerShell запрещает запуск скрипта активации, выполните один раз:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
или используйте командную строку (cmd): `.venv\Scripts\activate.bat`.

### macOS / Linux

```bash
cd PhishGuardAI
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

После запуска откройте в браузере адрес, который покажет Streamlit (обычно http://localhost:8501).

### Тесты и эксперимент

```bash
python -m pytest
python experiments/evaluate.py
```

Скрипт эксперимента принимает параметры `--threshold` (порог индекса) и `--output-dir` (папка для результатов). Результаты сохраняются в `experiments/results/evaluation_results.csv` и `evaluation_summary.json`; итог последнего запуска также показывается на вкладке «О проекте».

## Правила анализа

Каждое правило имеет постоянный идентификатор, категорию, степень, доказательство, объяснение, рекомендуемое действие и вклад в индекс. Описания и веса хранятся в `content/rules.json`.

| ID | Признак | Степень | Баллы |
|---|---|---|---|
| URL_CREDENTIALS | Учётные данные в адресе (символ @) | сильный | 25 |
| URL_IP_HOST | IP-адрес вместо доменного имени | умеренный | 10 |
| URL_HTTP | HTTP вместо HTTPS | слабый | 5 |
| URL_MANY_SUBDOMAINS | Необычно много поддоменов | слабый | 5 |
| URL_LONG | Чрезмерно длинный адрес | слабый | 5 |
| URL_IDN | Интернационализированное имя (Punycode) | слабый | 5 |
| URL_MIXED_SCRIPT | Смешение латиницы и кириллицы в одной метке | сильный | 25 |
| URL_PERCENT_ENCODED_HOST | Закодированные символы в имени хоста | умеренный | 10 |
| URL_SHORTENER | Сервис сокращения ссылок (скрытый адрес назначения) | умеренный | 10 |
| URL_BRAND_IN_SUBDOMAIN | Название бренда в поддомене чужого домена | сильный | 25 |
| URL_BRAND_NEAR_MATCH | Домен, похожий на официальный | сильный | 25 |
| URL_BRAND_TOKEN_IN_DOMAIN | Название бренда как часть чужого домена | умеренный | 10 |
| MSG_URGENCY | Давление срочностью | слабый | 5 |
| MSG_ACCOUNT_THREAT | Угроза блокировки аккаунта | умеренный | 10 |
| MSG_CREDENTIAL_REQUEST | Запрос пароля или одноразового кода | сильный | 25 |
| MSG_PAYMENT_REQUEST | Запрос оплаты или данных карты | умеренный | 10 |
| MSG_PRIZE | Неожиданный приз или выплата | умеренный | 10 |
| MSG_LINK_LOGIN | Просьба перейти по ссылке и ввести данные | умеренный | 10 |

### Настраиваемые пороги (`content/rules.json` → `thresholds`)

| Параметр | Значение | Смысл |
|---|---|---|
| `long_url_length` | 100 | URL длиннее — признак URL_LONG |
| `max_subdomain_levels` | 2 | больше уровней поддомена — признак URL_MANY_SUBDOMAINS (`www.example.com` — 1 уровень) |
| `brand_min_length_for_near_match` | 6 | расстояние редактирования считается, только если бренд и метка домена не короче 6 символов |
| `brand_max_edit_distance_short` / `_long` | 1 / 2 | допустимое расстояние для названий короче / от `brand_long_name_length` (9) символов |
| `max_url_length` | 4096 | максимальная длина вводимого URL |
| `max_message_chars` | 20000 | максимальная длина сообщения |
| `max_urls_per_message` | 10 | сколько уникальных ссылок из сообщения анализируется |
| `evaluation_threshold` | 25 | порог класса «подозрительный» в эксперименте |

### Правила брендов

Используется небольшой **иллюстративный** список официальных доменов (`content/brand_domains.json`). Он ограничен, требует регулярного обновления и **не является полным списком разрешённых доменов**. Срабатывают только определённые шаблоны:

1. Название бренда — отдельное слово в поддомене (`paypal.com.secure-login.example`), а регистрируемый домен не официальный.
2. Метка регистрируемого домена совпадает с названием бренда после замены похожих символов (`g00gle`, кириллические «а», «р», «е»…), удаления дефисов или отличается на 1–2 символа (`microsfot`).
3. Название бренда — отдельное слово через дефис в чужом домене (`tinkoff-bonus.test`).

Подстроки не считаются совпадением: `cloud.example.com` не похож на `icloud`, `bank.example` — на `tbank`. В доказательстве всегда показан официальный домен, с которым велось сравнение.

### Проверка символов

Смешение алфавитов проверяется **только для латиницы и кириллицы** в пределах одной метки имени хоста. Это не полная защита от подмены символов Unicode. Интернационализированные домены законны (например, зона .рф), поэтому признак URL_IDN слабый и требует проверки в контексте.

## Индекс подозрительных признаков

Индекс — сумма явно заданных весов сработавших правил: сильный признак — 25 баллов, умеренный — 10, слабый — 5. Каждое правило учитывается один раз для ссылки или текста, даже если фраза повторяется. Результат ограничен диапазоном 0–100.

| Индекс | Отображение |
|---|---|
| 0 | Признаки по текущим правилам не обнаружены |
| 1–24 | Есть признаки для проверки |
| 25–49 | Требуется внимательная проверка |
| 50–100 | Обнаружено несколько существенных признаков |

Индекс отражает сработавшие правила. Это не вероятность фишинга и не гарантия безопасности. Для сообщения индекс текста и индексы каждой ссылки показываются отдельно и не суммируются.

## Исследование

**Гипотеза:** «Объяснимый анализ ссылок и сообщений может помочь пользователям замечать признаки фишинга».

**Набор данных** (`content/evaluation_examples.json`) составлен и размечен вручную: 49 примеров (24 подозрительных, 25 безопасных или учебных). Он разделён на:

- **подмножество разработки** (16 примеров) — на нём отлаживались правила;
- **оценочное подмножество** (33 примера) — по нему правила и пороги не подбирались.

Все подозрительные адреса вымышлены и используют зарезервированные домены (`.example`, `.test`, `example.com/.net/.org`) или документационные IP-адреса (RFC 5737). В набор специально включены безопасные учебные тексты с терминами безопасности, чтобы показать ложные срабатывания. Для каждого примера указаны ожидаемые правила.

**Правило решения:** пример считается подозрительным, если индекс не ниже 25; для сообщения берётся наибольший из индексов текста и отдельных ссылок. Если метрика не определена (деление на ноль), скрипт явно сообщает об этом, а не подставляет 0 или 1.

**Оценка выполнена на небольшом учебном наборе примеров и не отражает точность на реальном интернет-трафике.** Оценочное подмножество не является репрезентативной выборкой реального фишинга. Образовательная эффективность инструмента требует отдельного исследования с участием пользователей; такое исследование не проводилось.

## Ограничения

- Анализ основан на правилах, а не на обученной модели.
- Содержимое веб-страниц не проверяется; ссылки не открываются.
- Живые базы угроз и репутационные сервисы не запрашиваются.
- Возможны ложные срабатывания и пропуски. Например, учебное предупреждение «никому не сообщайте код из СМС» срабатывает на правило запроса кода, а фразы русского языка распознаются по ограниченному набору шаблонов и форм слов.
- Название бренда в пути URL (`/sberbank/login`) правилами брендов не проверяется.
- Секреты в пути URL (например, токены сброса пароля в виде `/reset/abc123`) не скрываются; скрываются пароль в адресе и значения параметров с «чувствительными» именами (`token`, `password`, `code`, `session` и т. п.).
- Списки брендов и сокращателей ссылок малы и требуют обновления; официальные домены брендов в других зонах, отсутствующие в списке, могут вызвать срабатывание.
- Индекс не является вероятностью фишинга.

## Структура проекта

```
PhishGuardAI/
├── app.py                  интерфейс Streamlit
├── url_analyzer.py         разбор URL и правила для ссылок
├── message_analyzer.py     правила для текста, извлечение ссылок
├── scoring.py              каталог правил, индекс, рекомендации
├── reporting.py            HTML-отчёт
├── content/                правила, бренды, сокращатели, набор примеров

└── tests/                  тесты pytest (без доступа к сети)
```

## Технологии

Python 3.11+, Streamlit, стандартная библиотека Python, tldextract (используется только встроенная копия списка публичных суффиксов, без загрузки из сети), pytest.
